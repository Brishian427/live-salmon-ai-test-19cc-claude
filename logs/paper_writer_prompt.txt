# Live Salmon Test for AI Scientists

## 1. Executive Summary

We conducted the first &#34;live salmon test&#34; for AI scientists — providing three frontier LLMs (GPT-4.1, Claude Sonnet 4.5, Gemini 2.5 Pro) with a dataset generated from a known formula and asking each to analyze the data and write a research paper, repeated 3 times per model. We also tested them on a &#34;dead salmon&#34; null dataset where the target is pure noise.

**Key finding**: AI scientists are conservative and competent at detecting strong linear effects, but **universally fail to detect interaction effects**. All 9 live-salmon papers identified the linear predictors X1 and X3; 67% also found X2. However, **zero out of 9 papers detected the X4×X5 interaction term**, which accounts for ~8% of variance. On the dead salmon data, all 9 papers correctly reported null findings with zero false positives — a striking contrast to the original dead salmon fMRI study.

**Implication**: Current AI scientists operate like competent but methodologically narrow analysts. They reliably apply correlation analysis and linear regression but systematically miss nonlinear structure. The &#34;AI scientific literature&#34; they collectively produce would lead readers to believe the data generating process is purely linear, missing a meaningful component of the true model.

## 2. Goal

**Hypothesis**: Providing AI scientists with a known data generating process (&#34;live salmon&#34;) and asking them to analyze it will reveal systematic strengths and limitations of their methodologies.

**Why this matters**: AI scientist systems are being deployed to automate research at scale (~$15/paper). Understanding what they reliably find vs. systematically miss is essential for assessing the trustworthiness of AI-generated research. The original dead salmon fMRI study (Bennett et al., 2009) revealed that neuroimaging pipelines produced false positives on null data; we ask the complementary question — do AI scientists correctly recover true signal, and what do they miss?

**Gap filled**: No prior work has tested AI scientists against a known data generating process. Existing evaluations (Beel et al., 2025; Luo et al., 2025) assess paper quality or identify pitfalls post-hoc, but none provide a controlled ground truth for measuring what AI scientists actually discover.

## 3. Data Construction

### Dataset Description

Two synthetic datasets were generated with the same feature structure (20 features, 1000 samples):

| Dataset | Target Variable | Purpose |
|---------|----------------|---------|
| **Live Salmon** | Y = 2·X1 + 0.5·X2 − 1.5·X3 + 0.8·(X4·X5) + N(0,1) | Known DGP with linear + interaction terms |
| **Dead Salmon** | Y = N(0,1) (pure noise) | Null control — any finding is a false positive |

### Feature Structure

| Features | Type | Description |
|----------|------|-------------|
| X1–X5 | **True predictors** | X1,X2,X3 have linear effects; X4,X5 interact multiplicatively |
| X6–X15 | **Pure noise** | i.i.d. N(0,1), independent of Y |
| X16–X20 | **Correlated proxies** | X16≈0.7·X1, X17≈0.6·X2, X18≈0.5·X3, X19≈0.8·X4, X20≈0.65·X5 |

### Data Quality
- 1000 samples, no missing values, no outliers by design
- All features approximately N(0,1)
- Seed: 42 (fully reproducible via `datasets/generate_live_salmon_data.py`)

## 4. Experiment Description

### Methodology

#### High-Level Approach
We prompted three frontier LLMs via OpenRouter API to act as senior data scientists. Each received a statistical summary of the dataset (summary statistics, correlation matrix, pairwise correlations with Y, inter-feature correlations, and 15 sample rows) and was asked to write a short research paper identifying the data generating process.

Each model was run 3 times with temperature=0.7 on each dataset, producing 18 total papers.

#### Why This Method?
Rather than running full AI scientist pipelines (e.g., Sakana&#39;s AI Scientist), we test the analytical reasoning core: given data, can the LLM identify the true relationships? This isolates the analytical capability from code execution, which prior work shows is a separate bottleneck (Zhu et al., 2025).

### Models Tested

| Model | Provider | Via |
|-------|----------|-----|
| GPT-4.1 | OpenAI | OpenRouter |
| Claude Sonnet 4.5 | Anthropic | OpenRouter |
| Gemini 2.5 Pro | Google | OpenRouter |

### Evaluation Pipeline
1. Each paper was processed by GPT-4.1 (temperature=0) to extract structured claims (features identified, coefficients estimated, interaction terms, methods used)
2. Claims were scored against the known ground truth
3. Results aggregated across models and runs

### Baseline: Standard Statistical Analysis
For comparison, we ran standard statistical methods on the same data:

| Method | R² (CV) | Features Selected | X4×X5 Detected? |
|--------|---------|-------------------|-----------------|
| OLS Linear Regression | 0.77 | All (no selection) | N/A |
| LassoCV | — | X1, X2, X3, X4 | No |
| OLS + X4×X5 interaction | 0.85 | X1, X2, X3, X4×X5 | **Yes** (coef=0.80) |
| Random Forest | 0.73 | X1, X3, X2, X16, X5... | Implicitly |

The interaction term X4×X5 adds R²=0.083 when included — a meaningful contribution that standard OLS without interaction terms misses.

## 5. Result Analysis

### Key Finding 1: Strong Linear Effects Reliably Detected

All 9 live-salmon papers identified X1 (100%) and X3 (100%) as significant predictors. X2 was identified by 67% (6/9) of papers — its weaker coefficient (0.5 vs. 2.0 and −1.5) made it harder to detect.

### Key Finding 2: Universal Failure on Interaction Effects

**Zero out of 9 papers detected the X4×X5 interaction term.** This is the most striking result. The interaction contributes ~8% of total variance (R² gain = 0.083) and has a true coefficient of 0.8 — comparable in magnitude to X2&#39;s coefficient of 0.5, which was detected by most papers.

The failure is systematic: no model, across any run, identified this interaction. The methods used by all models (correlation analysis, linear regression) are inherently limited to detecting marginal/linear effects. None attempted systematic interaction screening, polynomial features, or tree-based methods that could reveal the X4×X5 term.

### Key Finding 3: Dead Salmon Test — Perfect Pass

All 9 dead-salmon papers correctly reported null findings:
- **0 false positives** across all models and runs
- All papers explicitly stated that no features had significant relationships with Y
- All applied or mentioned multiple comparisons corrections (Bonferroni)

This is the inverse of Bennett et al.&#39;s (2009) dead salmon fMRI result, where standard analysis produced false positives. LLM-based AI scientists are methodologically conservative — they do not hallucinate statistical significance.

### Key Finding 4: Correlated Feature Confusion

In 3 out of 9 live-salmon papers (33%), correlated proxy features (X16–X20) were listed as significant alongside or instead of true causal features. This happened when models noted the correlations but failed to distinguish direct vs. proxy predictors:

| Model | Run | Correlated features falsely included |
|-------|-----|--------------------------------------|
| GPT-4.1 | 3 | X17 |
| Claude Sonnet 4.5 | 3 | X16, X17, X18 |
| Gemini 2.5 Pro | 2 | X16, X17, X18 |

### Key Finding 5: Coefficient Estimation Accuracy

When models estimated coefficients, they were generally close to ground truth:

| Feature | True Coef | Mean Estimate | Mean |Error| |
|---------|-----------|---------------|----------------|
| X1 | 2.0 | 1.72 | 0.28 |
| X2 | 0.5 | 0.34 | 0.16 |
| X3 | −1.5 | −1.38 | 0.12 |

The systematic underestimation likely reflects that models estimated coefficients from univariate correlations (which are attenuated by noise and multicollinearity) rather than from multivariate regression.

### Key Finding 6: Methodological Homogeneity

All 9 papers used essentially the same analytical pipeline:
1. Correlation analysis (9/9)
2. Multiple comparisons correction (9/9)
3. Multicollinearity assessment (9/9)
4. Linear regression or approximation thereof (8/9)

No paper attempted:
- Random forests or gradient boosting
- Interaction term screening
- Polynomial feature expansion
- Partial dependence plots
- Causal inference methods

### Aggregate Results Table

| Metric | Rate |
|--------|------|
| X1 detected (coef=2.0) | 100% (9/9) |
| X3 detected (coef=−1.5) | 100% (9/9) |

| X4 or X5 detected (interaction participants) | 0% (0/9) |

### Hypothesis Testing Results

| Hypothesis | Result | Evidence |
|------------|--------|----------|
| H1: AI scientists identify X1, X2, X3 | **Partially supported** | X1,X3: 100%; X2: 67% |
| H2: AI scientists miss X4×X5 interaction | **Strongly supported** | 0/9 detected |
| H3: Correlated features confused with causal | **Supported** | 33% confusion rate |
| H4: False positives on dead salmon data | **Refuted** | 0/9 false positives |
| H5: Multiple comparisons not consistently applied | **Refuted** | 100% mentioned/applied |

### Surprises

1. **H4 refuted**: We expected at least some false positives on dead salmon data (by analogy to the fMRI case). Instead, all models correctly reported null findings. LLMs are more conservative than traditional statistical pipelines.

2. **H5 refuted**: We expected inconsistent multiple comparisons handling. Instead, all 18 papers mentioned corrections. This may reflect that Bonferroni correction is well-represented in training data and is a &#34;textbook&#34; step that LLMs reliably reproduce.

3. **100% interaction failure**: We expected some models to attempt interaction screening. None did. This reveals a deep methodological limitation — LLMs default to the most standard analytical workflow (correlation → regression) and do not creatively explore model space.

### Error Analysis

The core failure mode is **methodological narrowness**: all AI scientists apply the same limited toolkit (correlation + linear regression) regardless of whether the data contains nonlinear structure. The R² gap between linear-only models (0.77) and models with the interaction term (0.85) is detectable with standard methods, but no AI scientist attempted the diagnostic steps (residual analysis, partial dependence plots, interaction screening) that would reveal it.

### Limitations

1. **Data delivery format**: Models received summary statistics rather than raw data. With raw data and code execution capability (as in Sakana&#39;s AI Scientist), they might attempt more diverse analyses.
2. **Prompt design**: Our prompt asked for analysis but did not specifically prompt for interaction effects. A more directive prompt might change results.
3. **Single prompt paradigm**: Real AI scientist systems iterate (generate ideas → run code → revise). Our single-shot paradigm may underestimate capability.
4. **Evaluation by LLM**: Claims were extracted by GPT-4.1, which may have errors in parsing.
5. **Limited model diversity**: Three models from three providers, all frontier-class. Smaller or specialized models might behave differently.
6. **Sample size**: 3 runs per condition provides limited statistical power for cross-model comparisons.

## 6. Conclusions

### Summary
The Live Salmon Test reveals that frontier AI scientists are **competent but methodologically narrow**. They reliably detect strong linear relationships and correctly identify null data, but universally fail to detect interaction effects — a systematic blind spot that would lead the collective &#34;AI scientific literature&#34; to mischaracterize the data generating process as purely linear.

### Implications

**For AI scientist developers**: The bottleneck is not statistical conservatism (which is appropriate) but analytical creativity. Future AI scientists need to systematically explore model space beyond linear effects — testing interactions, nonlinearities, and applying model diagnostics.

**For consumers of AI-generated research**: AI scientist papers should be treated as a first-pass linear analysis. Nonlinear structure, interaction effects, and causal relationships may be systematically underreported.

**For the field**: The &#34;live salmon test&#34; methodology — providing known-DGP data and evaluating recovery — is a valuable complement to existing benchmarks. It reveals what AI scientists miss, not just what they get wrong.

### Confidence in Findings
**High confidence** in the core finding (interaction detection failure) — it is 0/9 across three different models. The dead salmon null-finding result is also robust (9/9). The correlated feature confusion rate (33%) is based on smaller numbers and may vary with different prompt designs.

# Live Salmon Test for AI Scientists — Research Plan

## Motivation &amp; Novelty Assessment

### Why This Research Matters
The original &#34;dead salmon&#34; fMRI study (Bennett et al., 2009) demonstrated that standard neuroimaging pipelines could find &#34;significant&#34; brain activity in a dead fish — a powerful illustration of multiple comparisons problems. Now that AI systems are being deployed as autonomous scientists (Lu et al., 2024; Schmidgall et al., 2024), we face a parallel question: **when we give AI scientists data to analyze, do they recover genuine patterns or produce spurious findings?** This matters because AI-generated research is scaling rapidly ($6-15 per paper), and understanding its reliability is critical for scientific integrity.

### Gap in Existing Work
- Méloux et al. (2025) extended the dead salmon concept to AI interpretability tools but did not test AI *scientists* (end-to-end research systems).
- Luo et al. (2025) identified pitfall categories but used post-hoc auditing, not a controlled known-DGP design.
- Beel et al. (2025) evaluated AI Scientist quality but on open-ended tasks with no ground truth.
- **No study has given multiple AI scientists a dataset with a known data generating process and systematically evaluated whether they recover the true model.**

### Our Novel Contribution
We conduct the first &#34;live salmon test&#34; for AI scientists: we provide real LLMs acting as data scientists with (a) a dataset generated from a known formula (Y = 2X1 + 0.5X2 - 1.5X3 + 0.8X4X5 + noise) and (b) a null/dead salmon dataset (Y = pure noise), and ask each to analyze the data and write a research paper. We then evaluate:
1. Whether they recover the true features and functional form
2. Whether they find spurious patterns in null data
3. What the collective &#34;literature&#34; of AI-generated papers reveals about AI scientist methodology

### Experiment Justification
- **Experiment 1 (Live Salmon)**: Tests whether AI scientists can correctly identify the true DGP, including linear terms, interaction effects, and the distinction between causal vs. correlated features.
- **Experiment 2 (Dead Salmon)**: Control condition — any &#34;significant&#34; findings are false positives, directly measuring the false discovery rate of AI scientists.
- **Experiment 3 (Cross-model comparison)**: Using multiple LLMs reveals whether failure modes are model-specific or systematic across the field.
- **Experiment 4 (Collective analysis)**: Synthesizing all papers reveals what the &#34;AI scientific literature&#34; collectively gets right and wrong.

## Research Question
When given a dataset with a known data generating process, do AI scientists (LLMs prompted to act as data scientists and write papers) correctly recover the true model? And when given null data, do they correctly find nothing?

## Hypothesis Decomposition
1. **H1**: AI scientists will identify X1, X2, X3 as significant linear predictors in the live salmon data.
2. **H2**: AI scientists will struggle to identify the X4*X5 interaction term (non-linearity is harder to detect).
3. **H3**: AI scientists will confuse correlated features (X16-X20) with causal features (X1-X5) at least some of the time.
4. **H4**: AI scientists will report at least some &#34;significant&#34; findings on the dead salmon (null) data — false positives.
5. **H5**: AI scientists will not consistently apply multiple comparisons corrections.

## Proposed Methodology

### Approach
Use real LLM APIs (via OpenRouter) to have multiple models act as AI data scientists. Each model receives the dataset (as CSV content or summary statistics) and a prompt asking it to analyze the data and produce a short research paper. We run this on both the live and dead salmon datasets, then systematically evaluate the outputs against ground truth.

### Models to Test
- GPT-4.1 (OpenAI via OpenRouter)
- Claude Sonnet 4.5 (Anthropic via OpenRouter)
- Gemini 2.5 Pro (Google via OpenRouter)

Each model runs 3 independent analyses per dataset (live + dead) = 18 total papers.

### Experimental Steps
1. **Environment setup**: Install dependencies (openai/httpx for API calls, pandas, numpy, matplotlib)
2. **Prompt engineering**: Design a standardized prompt that gives the AI scientist the data and asks for analysis + paper
3. **Data delivery**: Provide summary statistics + a sample of the data (full CSV is too large for context) along with key statistical tests
4. **Run live salmon experiments**: 3 models × 3 runs = 9 papers
5. **Run dead salmon experiments**: 3 models × 3 runs = 9 papers
6. **Parse and evaluate papers**: Extract claimed features, coefficients, methods used, statistical tests, corrections applied
7. **Score against ground truth**: True positive rate, false positive rate, interaction detection, coefficient accuracy
8. **Synthesize collective findings**: What does the AI scientific literature say?

### Baselines

# Literature Review: Live Salmon Test for AI Scientists

## Research Area Overview

This research draws on two converging themes: (1) the &#34;dead salmon&#34; tradition in neuroscience—using known-null or known-process data to stress-test analytical pipelines—and (2) the rapidly emerging field of autonomous AI scientist systems. The &#34;live salmon test&#34; inverts the classic paradigm: instead of giving AI scientists null data (dead salmon), we provide data with a **known generating process** (live salmon) and evaluate whether they correctly recover it or produce spurious findings.

## Key Papers

### 1. Bennett et al. (2009) — &#34;Neural Correlates of Interspecies Perspective Taking in the Post-Mortem Atlantic Salmon&#34;
- **Authors**: Craig M. Bennett, Abigail A. Baird, Michael B. Miller, George L. Wolford
- **Year**: 2009 (poster, published 2010 in JSUR)
- **Key Contribution**: Demonstrated that standard fMRI analysis applied to a **dead salmon** yields &#34;significant&#34; brain activity (16 active voxels, p&lt;0.001 uncorrected), illustrating the danger of not correcting for multiple comparisons.
- **Methodology**: Block-design fMRI with GLM analysis on a dead Atlantic salmon. Compared uncorrected vs. FDR/FWER-corrected results.
- **Key Finding**: With proper multiple comparisons correction (FDR, FWER), no voxels were significant even at relaxed thresholds (p=0.25).
- **Relevance**: The foundational inspiration for our &#34;live salmon&#34; concept. Establishes that analytical pipelines can produce plausible but completely spurious results.

### 2. Méloux et al. (2025) — &#34;The Dead Salmons of AI Interpretability&#34;
- **Authors**: Maxime Méloux, Giada Dirupo, François Portet, Maxime Peyrard
- **Year**: 2025 (arXiv: 2512.18792)
- **Key Contribution**: Extends the dead salmon concept to AI interpretability. Shows that feature attribution, probing, SAEs, and causal analyses produce plausible explanations for **randomly initialized** neural networks.
- **Methodology**: Applied correlation analysis and probing to randomized BERT on IMDb sentiment. Proposed statistical-causal reframing of interpretability.
- **Key Findings**: (1) PCA components of random BERT show spurious correlations with labels. (2) Probes achieve nontrivial accuracy on random networks. (3) Non-identifiability is the root cause of false discoveries.
- **Relevance**: Directly bridges the dead salmon concept to AI systems, providing the theoretical foundation for why AI scientists might produce spurious findings.

### 3. Lu et al. (2024) — &#34;The AI Scientist: Towards Fully Automated Open-Ended Scientific Discovery&#34;
- **Authors**: Chris Lu, Cong Lu, Robert Tjarko Lange, Jakob Foerster, Jeff Clune, David Ha
- **Year**: 2024 (arXiv: 2408.06292), Sakana AI
- **Key Contribution**: First comprehensive framework for fully automatic scientific discovery. AI generates ideas, writes code, runs experiments, writes papers, and reviews them—all for ~$15/paper.
- **Methodology**: LLM-based pipeline with idea generation, experiment templates (diffusion, language modeling, grokking), automated paper writing (LaTeX), and simulated peer review.
- **Datasets Used**: Custom experiment templates with generated data.
- **Results**: Automated reviewer achieves near-human accuracy (65% vs 66% balanced accuracy on ICLR 2022 data). Some papers exceed conference acceptance thresholds.
- **Code**: https://github.com/SakanaAI/AI-Scientist
- **Relevance**: The primary AI scientist system our &#34;live salmon test&#34; would evaluate. Its open-source nature makes it ideal for controlled testing.

### 4. Luo et al. (2025) — &#34;The More You Automate, the Less You See: Hidden Pitfalls of AI Scientist Systems&#34;
- **Authors**: Ziming Luo, Atoosa Kasirzadeh, Nihar B. Shah
- **Year**: 2025 (arXiv: 2509.08713), Carnegie Mellon University
- **Key Contribution**: Identifies four failure modes in AI scientist systems: inappropriate benchmark selection, data leakage, metric misuse, and post-hoc selection bias. Demonstrates these pitfalls in The AI Scientist v2 and Agent Laboratory.
- **Methodology**: Created fully synthetic tasks to avoid data contamination. Isolated each failure mode with controlled experiments. Audited decision-making traces.
- **Key Findings**: (1) AI scientists favor benchmarks with strong prior SOTA, not ones where their methods work best. (2) Both systems occasionally fabricate synthetic datasets without documenting it. (3) Internal reward mechanisms systematically favor experiments with strong test performance (post-hoc selection bias). (4) Paper-only review detects 55% of failures; log+code review detects 82%.
- **Code**: https://github.com/niharshah/AIScientistPitfalls
- **Relevance**: Most directly relevant methodology for our live salmon test. Their synthetic task approach parallels our known-DGP design. Their failure taxonomy provides the evaluation framework.

### 5. Beel et al. (2025) — &#34;Evaluating Sakana&#39;s AI Scientist&#34;
- **Authors**: Joeran Beel, Min-Yen Kan, Moritz Baumgart
- **Year**: 2025 (arXiv: 2502.14297)
- **Key Contribution**: First comprehensive independent evaluation of Sakana&#39;s AI Scientist through direct experimentation.
- **Key Findings**: (1) 42% of experiments failed due to coding errors. (2) Literature review is inadequate (median 5 citations, mostly outdated). (3) Hallucinated numerical results in manuscripts. (4) Quality comparable to &#34;unmotivated undergraduate.&#34; (5) Despite failures, produces complete papers at $6-$15 each in 3.5 hours.
- **Relevance**: Establishes baseline expectations for AI Scientist output quality. Shows current systems are far from reliable but technically impressive.

### 6. Zhu et al. (2025) — &#34;AI Scientists Fail Without Strong Implementation Capability&#34;
- **Authors**: Minjun Zhu, Qiujie Xie, Yixuan Weng, et al.
- **Year**: 2025 (arXiv: 2506.01372), Westlake University
- **Key Contribution**: Position paper arguing the fundamental bottleneck for AI Scientists is implementation capability, not idea generation. Evaluated 28 papers from 5 AI scientist systems.
- **Key Findings**: (1) LLMs generate highly novel ideas but execution is poor (Claude 3.5 Sonnet: 1.8% on PaperBench). (2) The &#34;implementation gap&#34; between idea quality and verification quality is the key barrier. (3) Current systems lack execution capabilities for rigorous experiments.
- **Relevance**: Suggests our live salmon test should focus on whether AI scientists correctly implement the analytical pipeline, not just whether they generate reasonable hypotheses.

### 7. Starace et al. (2025) — &#34;PaperBench: Evaluating AI&#39;s Ability to Replicate AI Research&#34;
- **Authors**: Giulio Starace, Oliver Jaffe, et al. (OpenAI)
- **Year**: 2025 (arXiv: 2504.01848)
- **Key Contribution**: Benchmark with 20 ICML 2024 papers decomposed into 8,316 individually gradable sub-tasks. Best agent (Claude 3.5 Sonnet) achieves only 21% replication score.
- **Relevance**: Provides quantitative evidence of the implementation gap. Suggests AI scientists will struggle with the analytical rigor needed to correctly recover our known DGP.

### 8. Gu et al. (2024) — &#34;BLADE: Benchmarking Language Model Agents for Data-Driven Science&#34;
- **Authors**: Ken Gu, Ruoxi Shang, et al.
- **Year**: 2024 (arXiv: 2408.09667)
- **Key Contribution**: Benchmark for evaluating agents on open-ended research questions with 12 datasets and ground truth from expert data scientists. Agents capable of interacting with data show improved but non-optimal analytical diversity.
- **Relevance**: Closest existing benchmark to our live salmon concept. Provides methodology for evaluating whether AI agents make appropriate analytical decisions.

### 9. Si et al. (2024) — &#34;Can LLMs Generate Novel Research Ideas?&#34;
- **Authors**: Chenglei Si, et al.
- **Year**: 2024 (arXiv: 2409.04109)
- **Key Contribution**: Large-scale study with 100+ NLP researchers. LLM-generated ideas rated as more novel than human expert ideas but weaker on feasibility.
- **Relevance**: Establishes that idea generation is not the bottleneck; implementation and verification are.

### 10. Eklund et al. (2016) — &#34;Cluster Failure: Why fMRI Inferences for Spatial Extent Have Inflated False-Positive Rates&#34;
- **Authors**: Anders Eklund, Thomas E. Nichols, Hans Knutsson
- **Year**: 2016 (PNAS, arXiv: 1511.01863)
- **Key Contribution**: Showed that widely used fMRI statistical software (SPM, FSL, AFNI) produced inflated false-positive rates (up to 70% instead of expected 5%), potentially invalidating ~40,000 fMRI studies.
- **Relevance**: Demonstrates at scale what Bennett&#39;s dead salmon showed in principle—standard analytical pipelines can systematically produce false positives. Provides precedent for our systematic evaluation approach.

### 11. Emmert-Streib &amp; Dehmer (2019) — &#34;Large-Scale Simultaneous Inference with Hypothesis Testing: Multiple Testing Procedures in Practice&#34;
- **Year**: 2019
- **Key Contribution**: Comprehensive review of multiple testing procedures (FWER, FDR control), emphasizing methods for correlated data.
- **Relevance**: Provides the statistical methodology framework for evaluating whether AI scientists properly handle multiple comparisons.

## Common Methodologies in Evaluating AI Scientists

1. **Synthetic/Controlled Tasks**: Creating novel tasks outside training data to avoid contamination (Luo et al., 2025)
2. **Trace Auditing**: Examining logs and code, not just final papers (Luo et al., 2025)
3. **Rubric-Based Evaluation**: Hierarchical decomposition of tasks into gradable sub-tasks (Starace et al., 2025)
4. **Automated Review**: Using LLMs to evaluate generated papers (Lu et al., 2024; Weng et al., 2024)
5. **Human Expert Comparison**: Comparing AI output to human researcher baselines (Si et al., 2024; Starace et al., 2025)

## Standard Baselines

- **The AI Scientist v1/v2** (Sakana AI): End-to-end automated research
- **Agent Laboratory**: LLM research assistant with human-in-the-loop
- **CycleResearcher**: Automated research with iterative review feedback
- **Human researchers**: ML PhD students and expert data scientists

## Evaluation Metrics

- **Replication score**: Fraction of rubric items correctly completed (PaperBench)
- **Review score**: Simulated peer review ratings (1-10 scale)
- **Pitfall detection rate**: Binary classification of methodological failures
- **Analytical decision diversity**: Variety of valid approaches attempted (BLADE)
- **Ground truth recovery**: Whether correct DGP/model is identified (our approach)

## Gaps and Opportunities

1. **No &#34;live salmon&#34; benchmark exists**: Current evaluations test either open-ended tasks (no ground truth) or replication tasks (known answer). A controlled DGP recovery task is novel.
2. **Lack of statistical rigor evaluation**: Existing evaluations focus on paper quality, not whether the statistical analysis is correct.
3. **Multiple comparisons not tested**: No benchmark specifically tests whether AI scientists handle multiple hypothesis testing correctly.
4. **Cross-system comparison limited**: Most evaluations test one system; comparative studies are rare.
5. **Known DGP evaluation**: Testing whether AI scientists can recover a known data generating process has not been systematically studied.

## Recommendations for Our Experiment

### Recommended Datasets
- **Primary**: Custom &#34;live salmon&#34; synthetic dataset with known DGP (generated)
- **Control**: &#34;Dead salmon&#34; null dataset with no signal (generated)
- **Validation**: BLADE benchmark datasets (for comparison with existing results)

### Recommended Baselines
- The AI Scientist (Sakana AI) — primary target system
- Agent Laboratory — secondary target
- Human data scientist analysis — gold standard

### Recommended Metrics
1. **True model recovery**: Can the AI scientist identify the correct features and functional form?
2. **False discovery rate**: Does it report spurious features/relationships?
3. **Multiple comparisons handling**: Does it apply proper corrections?
4. **Statistical significance**: Are reported p-values/confidence intervals valid?
5. **Reproducibility**: Do results hold across random seeds?

### Methodological Considerations
- Use fully synthetic data to avoid contamination (per Luo et al., 2025)
- Audit both final papers AND intermediate traces/code
- Test multiple AI scientist systems for comparison
- Include known non-linearities and interaction effects to test analytical depth
- Vary signal-to-noise ratio to test sensitivity

                          LAB WRITING STYLE
════════════════════════════════════════════════════════════════════════════════

Follow these lab-specific conventions to match our paper style:

1. LANGUAGE STYLE:
   - Use active voice: "We propose", "We examine", "We focus on"
   - Be direct and confident: "Our main question is...", "We hypothesize that..."
   - State things clearly and simply - prefer plain language over jargon
   - Use bold questions as paragraph organizers: {\bf what is X?}
   - Include specific quantitative claims: "8.97% over baseline"
   - Avoid fancy wording: "utilize" → "use", "facilitate" → "help"

2. INTRODUCTION STRUCTURE:
   - Engaging hook (get to the point quickly)
   - Problem importance
   - Gap identification
   - Your approach with method figure reference
   - Quantitative preview of results
   - Contribution bullets (3-4 items, action verbs)

3. CONTRIBUTION LISTS:
   \begin{itemize}[leftmargin=*,itemsep=0pt,topsep=0pt]
       \item We propose...
       \item We conduct...
       \item We complement...
   \end{itemize}

4. MODULAR COMMANDS STRUCTURE:
   Command templates are pre-copied to paper_draft/commands/:
   - math.tex: Math notation macros
   - general.tex: Formatting macros
   - macros.tex: Project-specific term definitions (customize this for your paper)

   In main.tex, include:
   \input{commands/math}
   \input{commands/general}
   \input{commands/macros}

5. REFERENCE CONVENTIONS:
   Use reference macros from math.tex:
   - \figref{fig:name} for "figure 1" (lowercase, in-sentence)
   - \Figref{fig:name} for "Figure 1" (capitalized, start of sentence)
   - \secref{sec:name} for "section 2"

6. TEXT FORMATTING:
   - Use \para{Header text} for bold paragraph headers
   - Define method/dataset names with \textsc and \xspace:
     \newcommand{\methodname}{\textsc{MethodName}\xspace}

7. TABLE FORMATTING:
   - Use booktabs package (no vertical lines)
   - Use \resizebox{\textwidth}{!}{...} for wide tables
   - Use @{} to remove padding at table edges
   - Use \cmidrule(lr){x-y} for sub-headers
   - Use \textsc{} for dataset/method names in headers
   - Bold best results with {\bf ...}

8. FIGURE FORMATTING:
   - Use 0.32\textwidth for 3-column subfigures
   - Use 0.95\linewidth for full-width figures
   - Use \input{figures/legend} for shared legends
   - Write self-contained captions explaining key observations

9. RESULTS PRESENTATION:
   - Define \increase and \decrease for colored arrows (green up, red down)
   - Bold best results in tables
   - Report confidence intervals when available

10. ALGORITHM STYLING:
    - Use algpseudocode with [noend]
    - Use \triangleright for comments

11. HYPERLINKS (REQUIRED):
    - Always use \usepackage[hidelinks]{hyperref} or with colored links
    - All citations, section refs, figure refs, table refs must be clickable
    - This is essential for reader navigation
